# Design — Update dependencies, refresh README, add CLAUDE.md

## Approach

Three ordered phases on a feature branch off `main`.

1. **Minor/patch batch.** All in-major updates are installed together and gated once. These are
   low-risk and attributing a failure among them is cheap.
2. **Majors, one by one.** Each major is installed alone, gated, and committed alone. A failure is then
   attributable to exactly one package, and reverting it is a single `git revert` or a discarded
   working tree.
3. **Documentation last.** `README.md` and `CLAUDE.md` are written after the dependency work so they
   state the versions that were actually adopted, not the ones that were hoped for.

The gate used after every step is the same three commands: `npm run lint:eslint:check`,
`npm run lint:prettier:check`, `npm run build`. The project has no test suite, so the build (which
type-checks) plus a manual pass over both routes is the strongest verification available.

## Files affected

| File                    | Role                                                                 |
| ----------------------- | -------------------------------------------------------------------- |
| `package.json`          | version bumps, pinning style preserved                               |
| `package-lock.json`     | regenerated by `npm install`                                         |
| `README.md`             | rewritten in English                                                 |
| `CLAUDE.md`             | new                                                                  |
| `.specs/BACKLOG.md`     | one entry per deferred major — only if a major is deferred           |
| `eslint.config.mjs`     | only if ESLint 10 requires a config change                           |
| `tsconfig.json`         | only if TypeScript 7 requires it (`baseUrl` is the likely candidate) |
| `src/app/**` (11 files) | only if `framer-motion` 14 requires mechanical import/API changes    |

Reuse: `README.md` reuses the existing `public/thumbnails/thumbnail.png`; no new asset is added.
`CLAUDE.md` points at `.specs/README.md` for the spec workflow instead of restating it.

## Technical decisions

### One major per commit

**Choice:** install, gate and commit each major separately.
**Why:** with no test suite, the only way to know which package broke the build is to change one at a
time.
**Rejected alternative:** `npx npm-check-updates -u` to move everything to latest in one step — a failure
could not be attributed to a package, and a partial revert would be guesswork.

### Threshold for keeping a major

**Choice:** a major is kept only if the gate passes after config-only or mechanical edits (a renamed
import, a renamed option, a removed deprecated flag). Anything that changes behaviour or requires
rewriting component logic means the package is reverted and a backlog entry is written with the exact
error observed.
**Why:** this work is maintenance; it must not turn into an unplanned migration.
**Rejected alternative:** making every major mandatory — it would tie the completion of the README and
CLAUDE.md to ecosystem compatibility this repository does not control.

### Explicit `npm install <pkg>@<version>` instead of the `update-dependencies` script

**Choice:** install explicit versions from the table in `spec.md`.
**Why:** `npm run update-dependencies` runs `npm-check-updates -i`, which is interactive and not
reproducible from the spec.
**Rejected alternative:** the interactive script — fine for ad-hoc use, but its outcome depends on what
is selected at the prompt.

### Pinning style is preserved

**Choice:** packages pinned exactly today (`next`, `react`, `prettier`, ...) stay exact; packages on a
range (`zod`, `next-themes`, `tailwindcss`) or on a bare major (`eslint`, `typescript`, `@types/*`) keep
that form.
**Why:** the mix is existing project convention; normalising it is a separate decision.
**Rejected alternative:** pinning everything exactly as part of this work — out of scope.

### CLAUDE.md is short and factual

**Choice:** commands, layout, conventions, pointer to `.specs/README.md`. No prose that restates what the
code or `package.json` already says.
**Why:** it is loaded into every agent session; every line costs context, and duplicated information goes
stale.
**Rejected alternative:** a comprehensive architecture document — belongs in `docs/` if ever needed.

## Known risks

| Risk                                                                                              | How it shows up                                  | Mitigation                                                                |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------- |
| TypeScript 7 not supported by Next or `@typescript-eslint`; `baseUrl` in `tsconfig.json` rejected | `npm run build` or lint fails                    | isolated commit; revert and record in the backlog                         |
| ESLint 10 outside the peer range of `eslint-config-next`                                          | `npm install` ERESOLVE, or lint crashes          | never force peer resolution; revert and record in the backlog             |
| `framer-motion` 14 API changes across 11 importing files                                          | type errors, or animations visibly broken        | build, then manual check of `/` and `/email-signature`                    |
| `@types/node` 26 ahead of the runtime (Node 22, `lts/jod`)                                        | types describe APIs that do not exist at runtime | kept only if the gate passes with zero source changes; otherwise reverted |
| No test suite                                                                                     | a regression passes CI unnoticed                 | manual QA checklist is part of the acceptance criteria                    |

## Failing safely

- Peer-dependency conflicts are never resolved with `--force` or `--legacy-peer-deps`. A conflict means
  the package is not adopted.
- A major that fails the gate is reverted, not patched around. The default on doubt is to stay on the
  current major and write the backlog entry.
- Nothing in this work is destructive or irreversible: every step is a commit on a feature branch.
